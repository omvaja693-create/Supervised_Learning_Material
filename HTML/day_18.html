Section 01Overview

Jab Classes Equal Nahi Hoti

Imbalanced dataset mein ek class ke samples bahut zyada hote hain aur doosri class ke bahut kam. Majority class dominant hoti hai; rare class ko minority class kehte hain.

Fraud detection mein 99.5% transactions genuine aur 0.5% fraud ho sakte hain. Agar model har transaction ko genuine bol de, accuracy high lagegi but fraud detection useless hoga.

Core IdeaData balance karna sirf class counts equal karna nahi; minority class ke meaningful patterns ko learn karwana hai without validation leakage.
Minority ClassSMOTEADASYNLeakage
🏥 Non-Technical Example

Hospital mein 10,000 routine patients aur 80 rare-disease patients hain. Agar model sabko “healthy” bol de, accuracy high hogi but rare disease cases miss ho jayenge. Focus minority recall par hona chahiye.

Section 025 W's Framework

What?

Class distribution unequal hone ki situation aur uske corrective strategies.

Why?

Minority class ko ignore karne wale misleading accuracy behavior ko reduce karne ke liye.

When?

Fraud, disease, defect, churn, spam jaise rare-event classification mein.

How?

Under-sampling, over-sampling, SMOTE, ADASYN, class weights aur threshold tuning.

Where?

Training data par, validation/test data ko untouched rakhte hue.

Risk?

Overfitting, noisy synthetic points, information leakage, and distribution shift.

Section 03The Imbalance Problem

Accuracy Ka Trap

ExampleAccuracy=990+01000=99%

Suppose 1000 samples mein 990 negatives and 10 positives hain. Model sabko negative predict karta hai: 990 TN, 10 FN. Accuracy 99%, but minority recall 0%.

Better questionsMinority class mein kitne detect hue? False alarms kitne hain? Precision, recall, F1, PR-AUC, ROC-AUC aur confusion matrix inspect karo.

Section 04Under-Sampling

Under-sampling mein majority class se kuch observations remove karke class distribution less skewed banaya jata hai.

Advantage

Training fast hoti hai, dataset smaller hota hai, majority dominance reduce hoti hai.

Risk

Useful majority information discard ho sakti hai, especially small datasets mein.

Selection mattersRandom under-sampling ke alawa informed methods use ho sakte hain, but original validation distribution ko preserve karna zaroori hai.

Section 05Over-Sampling

Minority Class ko Increase Karna

Over-sampling mein minority observations ko duplicate ya synthesize karke uski representation badhai jaati hai.

Random Over-Sampling

Minority rows ko replacement ke saath copy karta hai. Simple but duplicate memorization se overfitting ho sakta hai.

Synthetic Over-Sampling

Existing minority neighbors ke basis par new points banata hai. SMOTE aur ADASYN common examples hain.

Key ruleSampling sirf training fold par apply karo. Pehle oversample karke phir train/test split karoge to duplicate/synthetic information test set mein leak ho sakti hai.
🔗

Section 07ADASYN

Adaptive Synthetic Sampling

ADASYN SMOTE jaisa synthetic sampling karta hai, but har minority point ke liye equal samples generate nahi karta. Jahan minority sample ko majority neighbors se zyada difficulty hoti hai, wahan more synthetic samples create karta hai.

ADASYN cautionAgar difficult points actually noise ya mislabeled samples hain, ADASYN unke around extra synthetic noise create kar sakta hai.

Section 10Leakage-Safe Python Code

smote_pipeline.py
from imblearn.pipeline import Pipeline from imblearn.over_sampling import SMOTE from sklearn.preprocessing import StandardScaler from sklearn.linear_model import LogisticRegression from sklearn.model_selection import train_test_split, StratifiedKFold, cross_validate from sklearn.metrics import make_scorer, f1_score X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, test_size=.2, random_state=42) pipe = Pipeline([ ("scale", StandardScaler()), ("smote", SMOTE(random_state=42)), ("model", LogisticRegression(max_iter=1000)) ]) cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42) scores = cross_validate(pipe, X_train, y_train, cv=cv, scoring="f1") pipe.fit(X_train, y_train) predictions = pipe.predict(X_test)
imblearn Pipeline fold ke training portion par SMOTE apply karti hai; test fold untouched rehta hai.
adasyn_pipeline.py
from imblearn.over_sampling import ADASYN adaptive_pipe = Pipeline([ ("adasyn", ADASYN(random_state=42)), ("model", LogisticRegression(max_iter=1000)) ]) adaptive_pipe.fit(X_train, y_train)

🏆 Final Summary

  • Imbalance mein majority class dominance misleading accuracy create kar sakti hai.
  • Under-sampling majority rows reduce karta hai; information loss risk hota hai.
  • Over-sampling minority representation badhata hai; random copies overfit kar sakti hain.
  • SMOTE minority neighbors ke beech interpolation se synthetic points banata hai.
  • ADASYN difficult minority regions ko adaptively more samples deta hai, but noise amplify kar sakta hai.
  • Sampling ko training pipeline ke inside rakho aur untouched validation/test metrics se evaluate karo.
