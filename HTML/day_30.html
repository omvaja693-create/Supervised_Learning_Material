XGBoost in Supervised LearningXGBoost in Supervised Learning

XGBoost = Extreme Gradient Boosting. Yeh optimized machine-learning library hai, especially gradient-boosted decision trees ke liye popular. Supervised learning mein inputs X aur targets y use karke prediction function learn karta hai.

Non-technical example: improving an estimate
First estimate banao, current errors inspect karo, phir correction add karo. Har next correction existing combined estimate improve karne ki koshish karti hai. XGBoost mein corrections trees ke numeric leaf outputs se aati hain; loss derivatives aur regularization guide karte hain.
This lesson focuses on tree-based XGBoost classification using XGBClassifier and gbtree-style boosting. Library regression/ranking aur other booster options bhi support karti hai.

XGBoost powerful tabular baseline ho sakta hai; every dataset par best model hona guaranteed nahi. Clean data, leakage-free validation and meaningful features still essential hain.

5 W's: What, Why, When, How, WhereXGBoost in Supervised Learning

QuestionHinglish answer
What?Regularized gradient-boosting library; here sequential tree ensembles.
Why?Non-linear feature interactions learn karne, complexity control karne and efficient tree construction ke liye.
When?Structured/tabular supervised tasks with enough validation data and compute.
How?Current scores → loss gradients/Hessians → new tree → shrunken score update → repeat.
Where?Churn, risk screening, category prediction and other classification/regression systems; domain validation necessary.

Gradients, Hessians & Leaf ScoresXGBoost in Supervised Learning

Binary logistic loss ke liye current probability p and target y ∈ {0,1} use karo:

gi=pi−yihi=pi(1−pi)

g = loss first derivative w.r.t. raw score; h = second derivative. Ek proposed leaf ke rows ke gradients sum G, Hessians sum H.

w*=−GH+λ

This leaf-value formula assumes L2 regularization, no L1 penalty, and no leaf-step clipping. Actual tree building splits, constraints and other regularizers bhi consider karta hai. Final raw-score addition ηw* hai.

Worked leaf: two positive rows
Assume both y=1, current raw score F=0 → p=0.5.
Each g=−0.5, h=0.25 → G=−1, H=0.5.
λ=1 → w*=1/1.5≈0.6667.
η=0.3 → score update +0.2 → new p≈0.5498.
This is one assumed leaf assignment, not a demonstration that the learner necessarily chooses this split. Actual initial score/intercept can be data-estimated; F=0 is a teaching assumption here.

Train / Validation / Test & Early StoppingXGBoost in Supervised Learning

Train: 60%

Build trees and optimize training objective.

Validation: 20%

Monitor metric; choose best boosting round.

Test: 20%

Independent final evaluation only.

Early stopping stops adding rounds after a specified patience with no validation improvement. Validation use is model selection, so that set is not an untouched final test.

In modern sklearn interface, put early_stopping_rounds and eval_metric in the estimator constructor. Supply validation data via fit(..., eval_set=[...]). With multiple eval sets/metrics, monitoring rules matter; this example uses one validation set and one metric.

Never put final test set in eval_set while claiming independent test evaluation. Also, ordinary sklearn Pipeline does not automatically guarantee eval_set preprocessing matches transformed training inputs. Fit learned transforms on train only, then explicitly transform validation/test or use supported routing deliberately.

best_iteration is zero-based: selected rounds = best_iteration+1. sklearn-wrapper predictions use best iteration automatically when early stopping was used. Native Booster prediction requires its own explicit iteration handling; do not assume identical default behavior.

Python: Complete XGBoost ClassificationXGBoost in Supervised Learning

Installation: pip install xgboost scikit-learn numpy. On macOS an OpenMP runtime may also be needed; consult the package installation guide if import reports a missing library. Run blocks in order.

Python • 1. Verify a regularized leaf update
import numpy as np

y = np.array([1.0, 1.0])
p = np.array([0.5, 0.5])
gradients = p - y
hessians = p * (1 - p)
G, H = gradients.sum(), hessians.sum()
reg_lambda, learning_rate = 1.0, 0.3

leaf_weight = -G / (H + reg_lambda)
new_score = 0.0 + learning_rate * leaf_weight
new_probability = 1 / (1 + np.exp(-new_score))

print("G, H:", G, H)
print("Leaf weight:", leaf_weight)
print("New score/probability:", new_score, new_probability)
assert np.isclose(leaf_weight, 2 / 3)
assert np.isclose(new_score, 0.2)
Python • 2. Separate validation for early stopping
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from xgboost import XGBClassifier
import xgboost as xgb

X, y = make_classification(
    n_samples=1200, n_features=12, n_informative=7,
    n_redundant=2, weights=[0.7, 0.3],
    flip_y=0.02, random_state=42,
)
X_development, X_test, y_development, y_test = train_test_split(
    X, y, test_size=0.20, stratify=y, random_state=42
)
X_train, X_valid, y_train, y_valid = train_test_split(
    X_development, y_development, test_size=0.25,
    stratify=y_development, random_state=7
)

model = XGBClassifier(
    objective="binary:logistic",
    eval_metric="logloss",
    n_estimators=1000,
    learning_rate=0.05,
    max_depth=3,
    min_child_weight=2,
    subsample=0.8,
    colsample_bytree=0.8,
    reg_lambda=1.0,
    reg_alpha=0.0,
    gamma=0.0,
    tree_method="hist",
    early_stopping_rounds=25,
    random_state=42,
    n_jobs=1,
)
model.fit(X_train, y_train, eval_set=[(X_valid, y_valid)], verbose=False)
print("XGBoost version:", xgb.__version__)
print("Best iteration (zero-based):", model.best_iteration)
print("Selected rounds:", model.best_iteration + 1)
print("Best validation logloss:", model.best_score)

Dataset synthetic numeric binary task hai, no download. No learned preprocessing needed here. Native tree handling supports missing values, but infinity/invalid data and categorical representation still require checks. Dense zero is a real value; sparse absent entries can have different missing-value semantics.

Python • 3. Final evaluation & native JSON export
from sklearn.metrics import (
    classification_report, confusion_matrix, roc_auc_score,
    average_precision_score, log_loss,
)
from pathlib import Path
import json

# Final test was not used for early stopping or parameter selection.
predictions = model.predict(X_test)
positive_column = int(np.flatnonzero(model.classes_ == 1)[0])
probabilities = model.predict_proba(X_test)[:, positive_column]

print(confusion_matrix(y_test, predictions))
print(classification_report(y_test, predictions, zero_division=0))
print("ROC-AUC:", roc_auc_score(y_test, probabilities))
print("Average precision:", average_precision_score(y_test, probabilities))
print("Logloss:", log_loss(y_test, probabilities))

model.save_model("xgboost_classifier.json")
metadata = {
    "feature_names": [f"feature_{i}" for i in range(X.shape[1])],
    "classes": model.classes_.tolist(),
    "xgboost_version": xgb.__version__,
    "best_iteration": int(model.best_iteration),
}
Path("xgboost_metadata.json").write_text(
    json.dumps(metadata, indent=2), encoding="utf-8"
)

restored = XGBClassifier()
restored.load_model("xgboost_classifier.json")
assert np.array_equal(predictions, restored.predict(X_test))
assert np.allclose(
    model.predict_proba(X_test), restored.predict_proba(X_test)
)
print("Native JSON export/load parity passed.")
This is a fixed-parameter teaching baseline, not a claim of optimal tuning. Actual scores depend on data/settings/version. Model selection aur thresholds ko development data tak restrict karo; final test results ko further tuning feedback mat banao.

Native JSON/UBJ stores supported model state, not an entire preprocessing workflow or full training configuration. Preserve schema, versions and any fitted transforms separately. If a full sklearn Pipeline is pickled, only trusted files load karo. JSON export is not a reason to accept arbitrary unreviewed model files.

Tuning, Imbalance & PerformanceXGBoost in Supervised Learning

ParameterPractical interpretation
n_estimators + learning_rateRound budget vs per-round correction strength; tune jointly.
max_depth + min_child_weightControl structure and minimum child curvature mass.
reg_lambda / reg_alpha / gammaLeaf regularization and split acceptance controls.
subsample / colsample_bytreeIntroduce row/feature sampling to regularize; not AdaBoost sample-weight update.
scale_pos_weightBinary positive-class training weight multiplier; ratio negatives/positives is only a candidate heuristic.
tree_method='hist'Histogram-based split search, useful CPU baseline.
n_jobsThreads per fit; avoid oversubscribed nested CV parallelism.

For imbalance, inspect class-wise precision/recall, F1, average precision and confusion matrix. Weighting changes objective and probability behavior; automatically using class ratio is not universally best, especially if calibrated probabilities matter.

Tree-based XGBoost usually doesn't need feature scaling. Categorical support/encoding depends on API and data representation; raw arbitrary strings or ID numbers should not be silently treated as meaningful ordered quantities.

Cross-validation with early stopping needs fold-local validation and preprocessing. One shared eval_set carelessly passed through every fold can leak information. For a beginner, explicit three-way split is easier to audit.

Common mistakes: majority-vote explanation for gradient boosting; class-label residuals used for logistic objective; min_child_weight called row-count threshold; final test used in eval_set; wrong eval_set preprocessing; early_stopping_rounds copied into incompatible legacy fit signature.

One-Minute Revision

XGBoost = optimized gradient boosting. Trees add raw-score corrections. Binary logistic uses sigmoid; derivatives are p−y and p(1−p). Regularization constrains updates. Keep validation distinct from final test. best_iteration is zero-based. Save model plus schema and preprocessing.

Practice quest

Reproduce the default leaf update. Increase λ and observe smaller correction. Try negative vs positive G. In Python compare depth 2 vs 3 using development data; select settings and freeze them before final test. Inspect validation logloss curve without treating test as a tuning set.
