Tuning ka meaningHyperparameter Tuning

Hyperparameter tuning mein model ki configuration ke multiple options compare karte hain aur validation performance ke basis par suitable setting choose karte hain. Yeh training data memorize karne ki competition nahi; goal unseen data par better generalization hai.

Name clarification: “RandomSearchCV” ek common informal name hai. Scikit-learn ka actual class RandomizedSearchCV hai; Python import mein isi spelling ko use karo.
Non-technical example: chai ki recipe
Chai patti quantity, milk ratio aur boiling time recipe settings hain. Grid search har listed recipe combination try karega. Random search fixed budget mein randomly selected recipes try karega. Taste test validation jaisa hai; guests ko serve karna final test jaisa. Guests ki feedback repeatedly recipe selection mein use karoge toh independent final test khatam ho jayega.
ParameterHyperparameter
Model training se learn karta haiTraining/search configuration mein set hota hai
Linear model weights, learned split thresholdsTree max_depth, forest n_estimators, regularization C
Fit process determines valuesValidation-guided search chooses values

Random Forest ke tree split thresholds learned parameters hain. max_depth, min_samples_leaf aur max_features hyperparameters hain.

5 W's: What, Why, When, How, WhereHyperparameter Tuning

QuestionHinglish answer
What?Possible model configurations ka systematic comparison using cross-validation.
Why?Defaults har dataset ke liye ideal nahi; complexity, regularization aur compute ka balance choose karna hai.
When?Clean baseline aur suitable evaluation setup ready ho. Tuning leakage ya wrong labels fix nahi karta.
How?Search space + CV splitter + scoring metric define karo; candidates evaluate karo; chosen model refit karo.
Where?Classification, regression aur compatible scikit-learn pipelines. Deep-learning wrappers mein interface compatibility check karni hoti hai.

Safe Tuning WorkflowHyperparameter Tuning

Complete dataset
Training partition

Candidate search → cross-validation → select → refit on full training partition

Held-out test partition

Search mein kabhi nahi enters. Final chosen model ka independent evaluation.

Selected & refitted model → test once → report
  1. Task ke according metric aur split strategy choose karo.
  2. Final test set separate rakho.
  3. Training partition par CV ke andar candidates fit aur validate karo.
  4. Highest suitable mean CV score ke basis par winner select karo.
  5. refit=True winner ko full training partition par fit karta hai.
  6. Final test par metrics report karo; us score ko further tuning feedback mat banao.
Test score dekhkar search range change karna test leakage hai. Large search spaces validation noise ko overfit kar sakte hain, isliye highest CV score unbiased final performance estimate nahi.

5-fold CV mein training partition ko 5 subsets mein divide karte hain. Ek fold validate hota hai, remaining 4 fit ke liye use hote hain. Har candidate ke liye process repeat hota hai; fold scores ka average compare hota hai.

GridSearchCV: Exhaustive SearchHyperparameter Tuning

Grid search specified values ke all combinations evaluate karta hai. “Exhaustive” ka meaning tumhare defined grid ke andar exhaustive hai, universe ke all possible values nahi.

Worked grid: Random Forest
max_depth = [None, 5, 10]
min_samples_leaf = [1, 3]
max_features = ["sqrt", 0.8]
3 × 2 × 2 = 12 candidates. With 5-fold CV: 60 candidate-fold fits. With refit: 61 total estimator fits.
Ngrid=∏i=1dmiFtotal=Ngrid×K+1

mi = hyperparameter i ki values count. +1 single selected-model refit ko represent karta hai. refit=False ho toh +1 nahi.

Useful when

Search space small hai, promising range known hai, ya coarse search ke baad focused refinement chahiye.

Watch out

6 parameters × 5 values each = 15,625 candidates. With 5-fold CV, 78,125 fits before refit. Search quickly expensive ho sakta hai.

Conditional parameters ke liye param_grid list of dictionaries ho sakta hai. Har dictionary ka product separately compute karke counts add karte hain; incompatible combinations avoid hote hain.

RandomizedSearchCV: Budgeted ExplorationHyperparameter Tuning

Randomized search param_distributions se candidate configurations sample karta hai. n_iter sampled configurations ka budget hai—epochs, CV folds ya model ke trees ki count nahi.

Worked budget
n_iter=10, cv=5 → 50 candidate-fold fits + 1 refit = 51 fits. Large search space ko enumerate karna necessary nahi. Sampled choices useful ho sakti hain, lekin optimum find hona guaranteed nahi.
Search space typeSampling behavior
All parameter values are finite listsCombinations sample without replacement; n_iter exceeds total combinations toh all available candidates use hote hain
At least one scipy distributionSampling with replacement; repeated configurations possible
randint(80, 161)Integer values 80 through 160; upper bound excluded
loguniform(0.001, 100)Multiplicative scales across wide positive range explore karne ke liye useful
Search random_state sampled configurations control karta hai. Estimator ka seed model randomness control karta hai. CV splitter ka seed shuffled folds control karta hai. Reproducibility ke liye teeno independently set karo.

Random search broader spaces mein useful exploration strategy hai, lekin automatically grid se better nahi. Coarse random search → smaller targeted grid ek practical workflow hai.

Fair comparison ke liye same data split, same folds aur same scoring use karo. Different candidate budgets aur training times report karo. Final test pe winner choose mat karo.

Score ka direction

Scikit-learn scorers higher-is-better convention follow karte hain. f1_macro high better hai. Regression mein neg_mean_squared_error less negative better hai; displayed MSE ke liye sign reverse karo.

scoring=None estimator ka default score use karta hai (many classifiers: accuracy; many regressors: R²). Business objective ke according explicit scoring better hai.

Python: Tune a Random ForestHyperparameter Tuning

Previous lesson ke Random Forest ko Wine dataset par tune karenge. Neeche blocks order mein ek script/notebook mein run karo. Dependencies: pip install scikit-learn scipy numpy.

Python • 1. Setup & baseline
from sklearn.datasets import load_wine
from sklearn.model_selection import (
    train_test_split, StratifiedKFold,
    GridSearchCV, RandomizedSearchCV,
)
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report, f1_score
from sklearn.base import clone
from scipy.stats import randint

X, y = load_wine(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42
)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
base = RandomForestClassifier(
    n_estimators=100, random_state=42, n_jobs=1
)

# Baseline uses training-only CV, not the final test set.
from sklearn.model_selection import cross_val_score
baseline_scores = cross_val_score(
    clone(base), X_train, y_train, scoring="f1_macro", cv=cv
)
print("Baseline mean CV F1:", baseline_scores.mean())
Python • 2. GridSearchCV
grid = GridSearchCV(
    estimator=clone(base),
    param_grid={
        "max_depth": [None, 5, 10],
        "min_samples_leaf": [1, 3],
        "max_features": ["sqrt", 0.8],
    },
    scoring="f1_macro",
    cv=cv,
    refit=True,
    n_jobs=-1,
    error_score="raise",
)
grid.fit(X_train, y_train)
print("Grid candidates:", len(grid.cv_results_["params"]))
print("Best parameters:", grid.best_params_)
print("Best mean CV F1:", grid.best_score_)
Python • 3. RandomizedSearchCV
random_search = RandomizedSearchCV(
    estimator=clone(base),
    param_distributions={
        "n_estimators": randint(80, 161),
        "max_depth": [None, 4, 6, 10, 15],
        "min_samples_leaf": randint(1, 6),
        "max_features": ["sqrt", 0.5, 0.8],
    },
    n_iter=10,
    scoring="f1_macro",
    cv=cv,
    refit=True,
    random_state=42,
    n_jobs=-1,
    error_score="raise",
)
random_search.fit(X_train, y_train)
print("Random candidates:", len(random_search.cv_results_["params"]))
print("Best parameters:", random_search.best_params_)
print("Best mean CV F1:", random_search.best_score_)

Search level par parallelism enabled hai, forest n_jobs=1 use karta hai to avoid nested worker overload. error_score="raise" teaching/debugging mein invalid combinations ko immediately surface karta hai.

Python • 4. Results & final evaluation
# Compare methods using training-only CV scores.
# Tie policy: prefer the focused grid in this example.
winner = grid if grid.best_score_ >= random_search.best_score_ else random_search
results = winner.cv_results_
top_indices = sorted(
    range(len(results["params"])),
    key=lambda i: results["rank_test_score"][i],
)[:3]

for i in top_indices:
    print(
        results["params"][i],
        "mean:", round(results["mean_test_score"][i], 4),
        "std:", round(results["std_test_score"][i], 4),
        "fit seconds:", round(results["mean_fit_time"][i], 3),
    )

# best_estimator_ is already refitted on all X_train.
final_model = winner.best_estimator_
predictions = final_model.predict(X_test)
print("Chosen method:", type(winner).__name__)
print("Final test macro F1:", f1_score(y_test, predictions, average="macro"))
print(classification_report(y_test, predictions, zero_division=0))
This small dataset ek teaching demo hai. Exact scores version/settings ke saath vary kar sakte hain. Small CV score differences ko guaranteed improvement mat samjho; fold variability aur runtime bhi inspect karo. Test performance report karne ke baad configuration freeze karo.

Pipelines, Leakage & Nested CVHyperparameter Tuning

Scaling, imputation, feature selection aur resampling learned preprocessing hain. Inhe CV ke bahar full dataset par fit karoge toh validation information training mein leak ho sakti hai. Pipeline har fold ke training subset par preprocessing fresh fit karne mein help karta hai.

Python • 5. Leakage-safe scaling example
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("scale", StandardScaler()),
    ("model", LogisticRegression(max_iter=2000)),
])
pipeline_search = GridSearchCV(
    pipeline,
    param_grid={"model__C": [0.01, 0.1, 1, 10, 100]},
    scoring="f1_macro",
    cv=cv,
    n_jobs=-1,
    refit=True,
)
# Alternative-model practice; training data only.
pipeline_search.fit(X_train, y_train)
print("Pipeline parameters:", pipeline_search.best_params_)
print("Pipeline mean CV F1:", pipeline_search.best_score_)

model__C mein double underscore pipeline step aur parameter ko connect karta hai. Logistic Regression ko scaling useful hai; Random Forest generally scaling require nahi karta. SMOTE/ADASYN use ho toh imblearn.pipeline.Pipeline ke andar sampling karo, CV se pehle full data par nahi.

Nested CV ka idea

Outer training fold
→
Inner CV tuning
→
Outer validation fold evaluation

Inner loop hyperparameters select karta hai. Outer loop complete tuning procedure evaluate karta hai. Outer validation fold inner search ko visible nahi hota. Nested CV selection bias reduce karne mein help karta hai, lekin compute cost increase hoti hai.

Pipeline example ek optional separate exercise hai. Agar usse RF ke against model selection mein include karna hai, final test evaluate karne se pehle training-only CV par comparison karo.

Common Mistakes & Practical ChecklistHyperparameter Tuning

MistakeBetter habit
Training accuracy maximize karnaValidation/CV metric optimize karo
Test set par repeated tuningHeld-out test preserve karo
Entire dataset scale before CVLearned preprocessing pipeline mein fit karo
n_iter ko epochs samajhnan_iter sampled configurations ka count hai
Huge grid without estimateCandidates × folds + refit count calculate karo
Default scoring without checkingTask-aligned explicit metric choose karo
Random split for temporal/entity dataTemporal/group-aware split use karo
Nested n_jobs=-1 everywhereParallelism ek layer par control karo
Best CV score ko final guarantee samajhnaSeparate test / nested CV, uncertainty aur runtime report karo

Read the search object

best_params_ selected configuration; best_score_ selected mean CV score; best_estimator_ refitted model when enabled; cv_results_ all candidates, ranks, fold scores aur timings. In results mein “test_score” CV validation score hai, final test-set score nahi.

Multiple metrics ke liye scoring={"f1": "f1_macro", "accuracy": "accuracy"} aur refit="f1" selection metric define karte hain. With refit=False, fitted winner available nahi hota; selected parameters se fresh estimator manually fit karo.

Practice quest: 3 experiments

1. Small grid ka candidate count manually verify karo.
2. Same folds par random budget 5 vs 10 compare karo; compute and CV results record karo.
3. Promising region mein focused grid build karo without looking at final test. Ek frozen winner ko final test par evaluate karo.

One-Minute Revision

Grid = all defined combinations. Randomized = sampled budget. CV = validation within training partition. Pipeline = fold-safe preprocessing. Refit = winner retrained on all provided training data. Test = independent final evaluation. More search is not a guarantee of better generalization.
