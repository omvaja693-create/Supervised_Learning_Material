Bagging: Bootstrap AggregatingBagging Ensemble Technique

Bagging ka full form Bootstrap Aggregating hai. Same type ke base estimator ki multiple copies alag bootstrap samples par fit hoti hain. Predictions combine karke single fitted model par dependency kam karte hain.

Non-technical example: survey panels
Ek survey ke participants se multiple panels banate hain. Selection replacement ke saath hai, so same person ek panel mein repeat ho sakta hai aur kuch participants absent honge. Har panel se ek estimate banao, phir estimates combine karo. Analogy training-data resampling aur aggregation ko illustrate karti hai.

Bootstrap

Training rows ko replacement ke saath sample karna.

Aggregate

Base predictions ko voting/probability average ya numerical average se combine karna.

Classification aur regression dono mein useful. Decision trees common base learners hain because small data changes se unki fitted structure change ho sakti hai.

Bootstrap Sampling: Replacement ka MeaningBagging Ensemble Technique

Original training rows A, B, C, D, E hain. Five replacement draws mein A, C, C, E, A mil sakte hain. Total 5 draws, lekin only 3 unique rows. B aur D us estimator ke bag mein absent hain.

EstimatorBootstrap bag (5 draws)Unique in-bag rowsOut-of-bag rows
Model 1A, C, C, E, AA, C, EB, D
Model 2B, D, A, B, EA, B, D, EC
Model 3C, E, D, D, CC, D, EA, B

Bootstrap original data ka new information source nahi; same training information ko different multiplicities mein reuse karta hai. Train/test split pehle banao; resampling training partition only se ho.

P(row OOB)=(1−1n)m

Uniform independent replacement draws: n available rows, m draws. If m=n and n large, OOB probability ≈ e−1 ≈ 36.8%; expected unique in-bag fraction ≈ 63.2%. Exact counts per bag vary. Smaller bags change these percentages.

Without replacement sampling duplicates nahi create karta. Scikit-learn's bagging API supports that mode too, but ordinary bootstrap bagging ka defining sampling mode replacement hai.

  1. Separate held-out test set.
  2. Draw multiple bootstrap samples from training data.
  3. Fit one estimator on each sample.
  4. At inference, obtain each estimator output.
  5. Combine predictions; evaluate independent data.
Bagging is not boosting: learner 2 does not inherently train to correct learner 1's mistakes. Resampling and fit steps are independent.

Prediction Aggregation: Classifier & RegressorBagging Ensemble Technique

Classification

Conceptual bagging often explained through majority class votes. In BaggingClassifier, base estimators with predict_proba have their class probabilities averaged, then highest aggregate probability wins. If base estimators lack probabilities, predicted-label vote proportions are used.

p¯(c|x)=1B∑b=1Bpb(c|x)
Base output P(Class 1)Hard voteMean probability
0.51, 0.51, 0.01Two Class 1 labels → Class 10.3433 → Class 0

Probability averaging aur hard votes different results de sakte hain. Tree leaf distributions mixed hon toh this distinction relevant hai. Probabilities automatically calibrated confidence nahi.

Regression

y^(x)=1B∑b=1By^b(x)

Predictions 100, 120, 110 → average 110. B = base estimator count. Regression numerical predictions average karta hai; class votes nahi.

Why It Helps: Variance & CorrelationBagging Ensemble Technique

Deep decision tree small training changes se different branches learn kar sakta hai. Multiple such predictors aggregate karne se some variation cancel ho sakti hai, especially when errors not perfectly correlated.

Var(mean)=σ2[ρ+1−ρB]

This illustration assumes equal-variance continuous predictor outputs and common pairwise correlation ρ. Yeh exact classification-error formula nahi. If ρ=0, variance drops with B. If ρ=1, averaging identical variation remove nahi karta.

Often useful

High-variance learners, enough useful variation, and noisy local model decisions.

Not magic

High bias, missing signal, label issues or shared leakage bagging automatically fix nahi karta.

More estimators stability improve kar sakte hain but computation and memory increase hoti hai. Test performance monotonic improve hona guaranteed nahi.

OOB Evaluation: Who Can Judge a Row?Bagging Ensemble Technique

Out-of-Bag (OOB) rows woh training examples hain jo specific estimator ke bootstrap bag mein absent the. Each row ko evaluate karne ke liye only those estimators aggregate karo jinhone us row ko bag mein nahi dekha.

Row B from the earlier table
B Model 1 aur Model 3 ke bags mein absent tha. B ka OOB prediction un dono se banao, not Model 2 se, kyunki Model 2 ne B training mein use kiya tha.

oob_score=True requires bootstrap=True. Default classifier OOB score accuracy hai; default regressor OOB score R² hai. Few estimators par some rows ko insufficient/no OOB coverage mil sakti hai.

OOB independent final test ka full replacement nahi, especially repeated tuning ke baad. Training-data-wide learned preprocessing before bagging OOB estimate ko fully independent nahi rehne de sakti. Learned transforms each base estimator ke Pipeline mein rakho; complete workflow ko suitable CV se evaluate karo.

Grouped or time-ordered observations mein naive row bootstrap domain relationships violate kar sakta hai. Appropriate split/resampling design use karo, random IID assumption blindly mat apply karo.

Python: Bootstrap, Classifier & RegressorBagging Ensemble Technique

Dependencies: pip install scikit-learn numpy. Each code block is standalone. All datasets available locally in scikit-learn; no external data download.

Python • 1. Inspect a bootstrap sample
import numpy as np

rows = np.array(list("ABCDE"))
rng = np.random.default_rng(42)
indices = rng.choice(len(rows), size=len(rows), replace=True)
bag = rows[indices]
oob_indices = sorted(set(range(len(rows))) - set(indices.tolist()))

print("Bootstrap draws:", bag.tolist())
print("Unique rows:", sorted(set(bag.tolist())))
print("OOB rows:", rows[oob_indices].tolist())
assert len(bag) == len(rows)
assert set(bag).isdisjoint(set(rows[oob_indices]))
Python • 2. BaggingClassifier vs one tree
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import BaggingClassifier
from sklearn.metrics import classification_report
from sklearn.base import clone

data = load_iris(as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(
    data.data, data.target, test_size=0.20,
    stratify=data.target, random_state=42
)
single = DecisionTreeClassifier(random_state=42)
bag = BaggingClassifier(
    estimator=DecisionTreeClassifier(),
    n_estimators=100,
    max_samples=1.0,
    max_features=1.0,
    bootstrap=True,
    oob_score=True,
    random_state=42,
    n_jobs=1,
)
cv = StratifiedKFold(n_splits=4, shuffle=True, random_state=42)
candidates = {"single_tree": single, "bagging": bag}
means = {}
for name, model in candidates.items():
    scores = cross_val_score(
        model, X_train, y_train, cv=cv,
        scoring="f1_macro", error_score="raise"
    )
    means[name] = scores.mean()
    print(name, "CV mean:", scores.mean(), "std:", scores.std())

# Fit bag on training partition to inspect OOB statistics.
bag.fit(X_train, y_train)
print("OOB accuracy:", bag.oob_score_)
print("First estimator draws:", bag.estimators_samples_[0][:10])
print("First estimator feature indices:", bag.estimators_features_[0])

# Freeze winner using training-only CV, then evaluate final test.
winner = max(means, key=means.get)
final_model = bag if winner == "bagging" else clone(single).fit(X_train, y_train)
print("Selected model:", winner)
print(classification_report(y_test, final_model.predict(X_test), zero_division=0))
print("Class order:", final_model.classes_)
print("Probabilities:", final_model.predict_proba(X_test.iloc[:1]))

DecisionTree default all candidate features inspect karta hai. Here bag max_features=1.0 and tree default settings use karte hain, so this is plain bagged trees, not Random Forest split-wise feature subsampling. Tree inputs numeric hain, so scaling generally unnecessary.

Python • 3. BaggingRegressor
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import BaggingRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error
import numpy as np

X, y = load_diabetes(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42
)
model = BaggingRegressor(
    estimator=DecisionTreeRegressor(),
    n_estimators=100,
    bootstrap=True,
    oob_score=True,
    random_state=42,
    n_jobs=1,
)
model.fit(X_train, y_train)
predictions = model.predict(X_test)
print("OOB R2:", model.oob_score_)
print("Test MAE:", mean_absolute_error(y_test, predictions))
print("Test RMSE:", np.sqrt(mean_squared_error(y_test, predictions)))

# Verify aggregation for this all-feature tree ensemble.
base_predictions = np.array([
    tree.predict(X_test[:, feature_indices])
    for tree, feature_indices in zip(model.estimators_, model.estimators_features_)
])
assert np.allclose(predictions, base_predictions.mean(axis=0))
print("Regression averaging verified.")
Teaching results illustrate workflow, not guaranteed performance improvement. CV macro F1, OOB accuracy, OOB R² and test RMSE different quantities hain—directly compare mat karo. Final test ko repeat tuning feedback mat banao.

Bagging Parameters & Related MethodsBagging Ensemble Technique

ParameterMeaning
estimatorBase learner template; fitted clones form ensemble
n_estimatorsNumber of fitted base models
max_samplesRows drawn per estimator; integer count or fraction
bootstrapSample rows with replacement if True
max_featuresFeature count/fraction drawn per estimator
bootstrap_featuresFeature sampling replacement flag
oob_scoreTraining OOB estimate; requires bootstrap
random_state / n_jobsReproducibility / parallelism

Bagging max_features chooses a feature subset for each base estimator. Random Forest's max_features typically controls candidates at each split. Same parameter name, different layer of operation.

Pasting uses row sampling without replacement. Random subspaces sample feature subsets; random patches sample rows and features. These related options fit the broader ensemble API.

Learned preprocessing needed ho, set estimator to a full Pipeline. Export complete fitted bagging object with schema and matching environment, not just one base model. Pickle only trusted artifacts se load karo.

Bagging vs Other EnsemblesBagging Ensemble Technique

TechniqueMain ideaTypical distinction
BaggingSame learner on bootstrapped rowsIndependent fits; variance reduction intuition
Random ForestBagged trees + split-wise feature randomnessOften reduces tree correlation further
BoostingSequential learners address objective/errorsLater fits depend on previous ensemble
VotingCombine separately specified estimatorsMay use different algorithms; no bootstrap requirement
StackingMeta-model learns from OOF base outputsAdditional learned aggregation layer
Common mistakes: duplicates ko bug samajhna; OOB row ko all models se evaluate karna; 36.8% ko every bag ka exact constant samajhna; max_features layers confuse karna; bagging se all bias/leakage solve hone ki expectation.

One-Minute Revision

Bagging = bootstrap + aggregate. Replacement allows repeats. OOB is estimator-specific. Classification uses averaged probabilities when available; regression averages numbers. Diversity matters. Validate complete workflow and preserve final test.
