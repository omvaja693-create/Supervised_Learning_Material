Project: Iris Ensemble AppEnsemble Project & Deployment

Is supervised-learning project mein flower measurements se setosa, versicolor or virginica predict karenge. Individual baselines compare karenge, soft voting aur stacking evaluate karenge, aur selected ensemble Streamlit app mein load karenge.

Non-technical intuition
Multiple judges flower measurements analyze karte hain. Voting their probability estimates combine karta hai; stacking ek coordinator learn karta hai from out-of-fold judge outputs. App user ko final species aur probability estimates show karta hai.
Deliverable is a tutorial with complete runnable project code and deployment instructions. A live cloud app is not automatically published. Learner apne repository and Streamlit account se deployment complete karega.

Architecture & Leakage BoundariesEnsemble Project & Deployment

OFFLINE TRAINING

Labeled data → train/test split → outer CV comparison → selected ensemble fit → final test → export

ONLINE INFERENCE

Raw measurements → schema validation → cached fitted ensemble → species + probabilities

Logistic Regression and KNN need appropriate scaling; Random Forest generally doesn't. Preprocessing har base estimator ke Pipeline mein hai, so internal stacking folds learn their own imputation/scaling.

Stack ke outside one globally fitted scaler rakhna internal OOF preprocessing ko fold-local nahi banata. Meta-model ko in-sample base predictions par train mat karo. Whole stack outer CV se evaluate karo; inner CV only meta-feature generation hai.

All candidates same outer folds and macro F1 use karte hain. This teaching project chooses the better of two ensemble candidates only. Individual baselines visible hain; agar baseline as good/better ho, ensemble superiority claim mat karo. Production mein complexity and latency bhi compare karo.

Complete train.pyEnsemble Project & Deployment

Below script run karke all generated files create honge. It compares three baselines plus two ensembles, then fits and exports selected voting/stacking model.

Python • train.py
from pathlib import Path
from importlib.metadata import version
import json
import pickle
import platform

import numpy as np
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.ensemble import RandomForestClassifier, VotingClassifier, StackingClassifier
from sklearn.metrics import classification_report, f1_score
from sklearn.base import clone

BASE = Path(__file__).resolve().parent
data = load_iris(as_frame=True)
X, y = data.data, data.target
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, stratify=y, random_state=42
)
base_models = [
    ("lr", Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("scale", StandardScaler()),
        ("model", LogisticRegression(max_iter=2000)),
    ])),
    ("rf", Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("model", RandomForestClassifier(
            n_estimators=80, min_samples_leaf=2,
            random_state=42, n_jobs=1
        )),
    ])),
    ("knn", Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("scale", StandardScaler()),
        ("model", KNeighborsClassifier(n_neighbors=7)),
    ])),
]
ensembles = {
    "soft_voting": VotingClassifier(
        estimators=base_models, voting="soft", n_jobs=1
    ),
    "stacking": StackingClassifier(
        estimators=base_models,
        final_estimator=LogisticRegression(max_iter=2000),
        stack_method="predict_proba",
        cv=StratifiedKFold(n_splits=3, shuffle=True, random_state=7),
        passthrough=False, n_jobs=1,
    ),
}
outer_cv = StratifiedKFold(n_splits=4, shuffle=True, random_state=42)
candidates = {name: clone(model) for name, model in base_models}
candidates.update(ensembles)
cv_results = []
scores_by_name = {}
for name, model in candidates.items():
    scores = cross_val_score(
        model, X_train, y_train, cv=outer_cv,
        scoring="f1_macro", error_score="raise", n_jobs=1,
    )
    scores_by_name[name] = float(scores.mean())
    cv_results.append({
        "name": name, "mean_f1": float(scores.mean()),
        "std_f1": float(scores.std()),
    })
    print(name, scores.mean(), scores.std())

# This project deploys the better of the TWO ensemble candidates.
# Individual baselines stay visible; do not claim guaranteed improvement.
selected_name = max(ensembles, key=lambda name: scores_by_name[name])
selected = clone(ensembles[selected_name]).fit(X_train, y_train)
pred = selected.predict(X_test)
proba = selected.predict_proba(X_test)
print("Selected ensemble:", selected_name)
print(classification_report(y_test, pred, zero_division=0))

packages = ["streamlit", "scikit-learn", "numpy", "pandas", "scipy"]
metadata = {
    "model_name": selected_name,
    "features": list(X_train.columns),
    "class_labels": selected.classes_.tolist(),
    "target_names": data.target_names.tolist(),
    "defaults": X_train.median().to_dict(),
    "minimums": X_train.min().to_dict(),
    "maximums": X_train.max().to_dict(),
    "python": platform.python_version(),
    "versions": {name: version(name) for name in packages},
}
with (BASE / "ensemble.pkl").open("wb") as file:
    pickle.dump(selected, file, protocol=pickle.HIGHEST_PROTOCOL)
with (BASE / "ensemble.pkl").open("rb") as file:
    restored = pickle.load(file)  # Own trusted artifact only.
assert np.array_equal(pred, restored.predict(X_test))
assert np.allclose(proba, restored.predict_proba(X_test))
(BASE / "metadata.json").write_text(
    json.dumps(metadata, indent=2), encoding="utf-8"
)
(BASE / "metrics.json").write_text(json.dumps({
    "cv_results": cv_results,
    "selected_ensemble": selected_name,
    "test_macro_f1": float(f1_score(y_test, pred, average="macro")),
    "test_report": classification_report(
        y_test, pred, output_dict=True, zero_division=0
    ),
}, indent=2), encoding="utf-8")
(BASE / "requirements.txt").write_text(
    "\n".join(f"{name}=={version(name)}" for name in packages) + "\n",
    encoding="utf-8",
)
print("Model, metadata, metrics and requirements exported.")
Soft-vote estimates necessarily calibrated nahi; validate calibration if probability quality matters. Stack's meta-model training OOF outputs use karti hai. Small CV differences and fold variability inspect karo; runtime bhi relevant hai.

Script learner choice final test report dekhkar change nahi karta. Final model only training partition par fit hota hai; held-out test remains independent of fitting. Final test evaluate karne ke baad retune/reselect mat karo without a new evaluation plan.

Export the Whole Fitted EnsembleEnsemble Project & Deployment

ensemble.pkl mein fitted voting/stacking object, base models, their pipelines, and—if stacking selected—fitted meta-model included hain. Sirf meta-model export karna incomplete inference workflow hoga.

ArtifactPurpose
ensemble.pklComplete fitted inference estimator
metadata.jsonFeature names/order, class mapping, training-only UI defaults and runtime versions
metrics.jsonBaseline/ensemble CV results and final held-out report
requirements.txtExact direct package versions recorded from training environment
Pickle deserialization arbitrary code execute kar sakta hai. Only trusted, reviewed project artifacts load karo. No user-uploaded pickle loader. Version/schema checks security sandbox nahi; trust must exist before pickle.load.

Native XGBoost JSON export from previous lesson arbitrary sklearn ensemble/pipeline ko save nahi karta. This project sklearn composite estimator hai, so trusted Python persistence with matching environment use hoti hai. Requirements pins alone OS/Python incompatibility solve nahi karte.

Training script reload karke same test input par labels/probabilities compare karta hai: serialization parity check. Model and metadata ko one release ki tarah update karo; mismatched files avoid karo.

Complete app.py: Cached InferenceEnsemble Project & Deployment

Python • app.py
from pathlib import Path
from importlib.metadata import version
import json
import pickle
import platform

import numpy as np
import pandas as pd
import streamlit as st

BASE = Path(__file__).resolve().parent
MODEL = BASE / "ensemble.pkl"
META = BASE / "metadata.json"
st.set_page_config(page_title="Iris Ensemble", layout="centered")

@st.cache_resource
def load_bundle(model_path, meta_path, model_stamp, meta_stamp):
    # Paths and timestamps form the cache key.
    metadata = json.loads(Path(meta_path).read_text(encoding="utf-8"))
    for name, expected in metadata["versions"].items():
        if version(name) != expected:
            raise ValueError(f"Version mismatch: {name}")
    if platform.python_version().split(".")[:2] != metadata["python"].split(".")[:2]:
        raise ValueError("Python major/minor mismatch")
    # Load ONLY the reviewed artifact produced by this project.
    with Path(model_path).open("rb") as file:
        model = pickle.load(file)
    if list(model.feature_names_in_) != metadata["features"]:
        raise ValueError("Feature schema mismatch")
    if model.classes_.tolist() != metadata["class_labels"]:
        raise ValueError("Class mapping mismatch")
    return model, metadata

st.title("Iris Ensemble")
st.caption("Flower measurements in centimeters")
try:
    model, metadata = load_bundle(
        str(MODEL), str(META),
        MODEL.stat().st_mtime_ns, META.stat().st_mtime_ns
    )
except Exception:
    st.error("Model unavailable. Check trusted files, schema and runtime versions.")
    st.stop()

st.caption("Selected ensemble: " + metadata["model_name"])
features = metadata["features"]
with st.form("flower"):
    values = {}
    columns = st.columns(2)
    for i, feature in enumerate(features):
        with columns[i % 2]:
            values[feature] = st.number_input(
                feature, min_value=0.01,
                value=float(metadata["defaults"][feature]), step=0.1,
            )
    submit = st.form_submit_button("Predict species")

if submit:
    row = pd.DataFrame([values], columns=features)
    if not np.isfinite(row.to_numpy()).all():
        st.error("Measurements must be finite numbers.")
        st.stop()
    outside = [
        feature for feature in features
        if values[feature] < metadata["minimums"][feature]
        or values[feature] > metadata["maximums"][feature]
    ]
    if outside:
        st.warning("Outside observed training range: " + ", ".join(outside))
    try:
        label = int(model.predict(row)[0])
        probabilities = model.predict_proba(row)[0]
    except Exception:
        st.error("Prediction failed. Check the model and input schema.")
        st.stop()
    names = [metadata["target_names"][int(c)] for c in model.classes_]
    st.success("Predicted species: " + metadata["target_names"][label])
    result = pd.DataFrame({"Species": names, "Probability": probabilities})
    st.dataframe(result, hide_index=True)
    st.bar_chart(pd.Series(probabilities, index=names, name="Probability"))
    st.caption("Educational demo. Model probabilities are not certainty.")

st.form inputs batch karta hai; submit par predictions generate hoti hain. st.cache_resource trusted fitted model across reruns cache karta hai. Model/metadata file timestamps arguments mein hain, so artifact updates new cache key banate hain.

Cached global resources shared ho sakte hain. Serving path mein model fit, mutable training or user-specific state store mat karo. Probabilities model estimates hain, not guaranteed correctness. Min/max training range warning only a useful signal, full out-of-distribution detector nahi.

Metadata labels and columns fixed schema preserve karte hain. model.classes_ probability columns ka correct order defines karta hai. DataFrame(..., columns=features) names/order stable rakhta hai; units cm hi rahni chahiye.

Deploy on Streamlit Community CloudEnsemble Project & Deployment

  1. Train locally and pass smoke tests.
  2. Create a GitHub repository with app.py, train.py, smoke_test.py, ensemble.pkl, metadata.json, requirements.txt and optional metrics.json.
  3. Exclude environment folders, caches and secrets. Include the trusted model file deliberately; generic *.pkl ignore rules may accidentally omit it.
  4. Community Cloud mein sign in karo, Create app select karo, then repository, branch and entrypoint app.py choose karo.
  5. Advanced settings mein compatible training Python version choose karo. Version unavailable ho toh supported Python environment mein retrain/re-export and regenerate pins.
  6. Deploy and inspect build/runtime logs. If app is nested, entrypoint ka correct relative path choose karo.
  7. Same local sample cloud app par test karo. Model selection, label order and probabilities consistent hon.
  8. Only after validation share app link and document demo limitations.

Troubleshooting & Production LimitsEnsemble Project & Deployment

SymptomCheck
Model unavailableFiles exist, same release, matching versions/Python, correct schema.
Input feature errorExact saved feature labels/order and centimeters.
Different prediction after deploySame artifact, dependencies, preprocessing and class mapping.
No result while typingForm needs submit; expected behavior.
Unexpected poor ensemble performanceCompare individual baselines; model diversity and calibration may be insufficient.
Stack CV score suspiciously perfectAudit OOF generation, base pipelines and data leakage.
App slowCache loading, small ensemble budget, avoid training in app.
Import/install errorInspect requirements pins, Python compatibility and logs.

Release Checklist

Training-only selection • full estimator exported • trusted artifacts • metadata/schema consistent • test reserved • direct pins recorded • clean inference errors • cache does not mutate • smoke tests pass • cloud verified • limitations disclosed.

Practice quest

Add AdaBoost or bagged trees to the comparison in training-only CV. Keep an ensemble selection policy explicit and record latency. Consider XGBoost only with compatible dependency handling; do not hand an outer eval_set into internal stacking folds without a valid design.
