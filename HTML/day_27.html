Ensemble Learning: Multiple Models, One DecisionVoting & Stacking

Ensemble learning multiple models ke outputs combine karta hai. Voting fixed combination rule use karta hai; stacking combination ko ek additional model se learn karta hai.

Non-technical example: committee decision
Teen advisors recommendation dete hain. Hard voting mein unke final choices count hote hain. Soft voting mein class-wise probability estimates combine hote hain. Stacking mein coordinator past out-of-sample recommendations se seekhta hai ki outputs ko kaise combine karna hai.
Committee analogy useful hai, but models human experts nahi. Diversity ka meaning useful differences in errors/representation hai—not just different model names.

Ensemble best individual model se better ho sakta hai, but improvement guaranteed nahi. Weak, highly correlated or poorly calibrated models result degrade bhi kar sakte hain.

Hard Voting: Labels ka MajorityVoting & Stacking

Each model predict() se class label deta hai. Uniform voting mein highest count wins. Weighted hard voting mein each predicted label assigned model weight contribute karta hai.

ModelPredicted labelUniform vote
Logistic RegressionClass 11 for Class 1
Random ForestClass 11 for Class 1
Naive BayesClass 01 for Class 0
EnsembleClass 12 vs 1
y^=argmaxc∑m=1Mwm𝟙(y^m=c)

M models; wm model weights; indicator 1 when model predicts class c. Uniform voting means every weight = 1.

Hard voting needs class predictions, not probabilities. Odd model count binary uniform vote ties avoid karta hai, but multiclass or weighted ties still possible. Scikit-learn hard-vote ties choose lowest encoded class.

Soft Voting: Average Class ProbabilitiesVoting & Stacking

Each estimator ko predict_proba() support karna chahiye. For each class probabilities average/weighted-average karo, then highest aggregate probability select karo.

Uniform soft result(0.51 + 0.51 + 0.01)/3 = 0.3433Predict Class 0

Hard labels uncertainty discard karte hain. Soft probabilities preserve score strength, but poorly calibrated overconfidence wrong influence de sakti hai. Naive Bayes probability caveat from previous lesson yahan especially relevant hai.

Soft voting automatically superior nahi. Well-calibrated classifiers prefer karo and validate. Actual estimator predict() always probability argmax se match kare, yeh universal guarantee nahi; lab intentionally simple binary argmax convention use karta hai.
05

Weighted Voting & Useful DiversityVoting & Stacking

weights=[2,1,1] first estimator ka influence double karta hai. Weights validation/CV se select karo, final test score dekhkar nahi. This tutorial non-negative weights use karta hai with positive total weight.

Good diversity

Different inductive biases: linear model, tree ensemble, probabilistic model. Distinct errors help combination.

False diversity

Same leakage, weak representation or almost identical errors multiple models mein repeat hon toh ensemble little benefit de sakta hai.

VotingClassifier fit() supplied estimators ke clones train karta hai. Original objects prefit hone par bhi fitted ensemble components ke liye named_estimators_ inspect karo.

Weights model accuracy percentages directly use karna universal best rule nahi. Class-wise strengths, calibration and error overlap evaluate karo.

Stacking: Learn the CombinationVoting & Stacking

Stacked generalization base models ke outputs ko new features banata hai. Meta-model / final estimator in output-features aur original labels se prediction learn karta hai. Unlike voting, combination fixed average nahi hota.

08

Out-of-Fold Predictions & LeakageVoting & Stacking

  1. Training partition ko K folds mein split karo.
  2. Each base model ka clone K−1 folds par fit karo.
  3. Held-out fold ke outputs collect karo.
  4. Repeat so every training row gets OOF outputs from each base model.
  5. Meta-model ko OOF output-features + training labels par fit karo.
  6. Deployment ke base models full training partition par fit karo; meta-model wahi OOF-trained model rehta hai.
Base models ko all training rows par fit karke same rows ke predictions se meta-model train karna overoptimistic signals create kar sakta hai. cv="prefit" OOF predictions generate nahi karta; same data dono layers ke liye use ho toh high overfitting risk hai.

Preprocessing boundary matters

Scaler/imputer/vectorizer ko each base estimator ke Pipeline mein rakho. Ek outer scaler full training partition par fit hokar internal stacking folds se pehle run kare, toh OOF feature preprocessing fold-local nahi rahegi.

Internal CV is not evaluation

Stacking ka cv meta-training features generate karta hai; final model ka unbiased score nahi. Outer cross-validation ya held-out test complete stack evaluate kare. Tuning repeatedly OOF/CV scores par karne se selection bias possible hai.

Time-series/grouped data ke liye appropriate split design chahiye. Standard K-fold ko blindly apply mat karo; stacking OOF generation mein each row exactly one held-out fold se prediction milne ki requirements bhi check karo.

Python: Voting & Stacking on IrisVoting & Stacking

Run these blocks in order. Dependencies: pip install scikit-learn numpy. Three base models training-only outer CV se compare honge; final test winner freeze hone ke baad evaluate hoga.

Python • 1. Base models and voting
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier, VotingClassifier, StackingClassifier
from sklearn.naive_bayes import GaussianNB
from sklearn.base import clone

data = load_iris(as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(
    data.data, data.target, test_size=0.20,
    stratify=data.target, random_state=42
)
base_estimators = [
    ("lr", Pipeline([
        ("scale", StandardScaler()),
        ("model", LogisticRegression(max_iter=2000)),
    ])),
    ("rf", RandomForestClassifier(
        n_estimators=80, min_samples_leaf=2, random_state=42, n_jobs=1
    )),
    ("nb", GaussianNB()),
]
outer_cv = StratifiedKFold(n_splits=4, shuffle=True, random_state=42)
candidates = {name: clone(model) for name, model in base_estimators}
candidates["hard_vote"] = VotingClassifier(
    estimators=base_estimators, voting="hard"
)
candidates["soft_vote"] = VotingClassifier(
    estimators=base_estimators, voting="soft"
)
cv_scores = {}
for name, model in candidates.items():
    scores = cross_val_score(
        model, X_train, y_train, cv=outer_cv,
        scoring="f1_macro", error_score="raise", n_jobs=1
    )
    cv_scores[name] = scores.mean()
    print(name, "CV mean:", scores.mean(), "std:", scores.std())
Python • 2. Evaluate the complete stack
inner_cv = StratifiedKFold(n_splits=3, shuffle=True, random_state=7)
stack = StackingClassifier(
    estimators=base_estimators,
    final_estimator=LogisticRegression(max_iter=2000),
    stack_method="predict_proba",
    cv=inner_cv,
    passthrough=False,
    n_jobs=1,
)
# Outer CV evaluates the WHOLE estimator.
# Inner CV creates OOF meta-training features inside each outer training fold.
scores = cross_val_score(
    stack, X_train, y_train, cv=outer_cv,
    scoring="f1_macro", error_score="raise", n_jobs=1
)
candidates["stack"] = stack
cv_scores["stack"] = scores.mean()
print("Stack CV mean:", scores.mean(), "std:", scores.std())
Python • 3. Freeze, test, export
from sklearn.metrics import classification_report, confusion_matrix
import pickle
import numpy as np

# Selection uses training-only CV; ties follow candidate insertion order.
winner_name = max(cv_scores, key=cv_scores.get)
final_model = clone(candidates[winner_name]).fit(X_train, y_train)
predictions = final_model.predict(X_test)
print("Chosen candidate:", winner_name)
print(confusion_matrix(y_test, predictions))
print(classification_report(y_test, predictions, zero_division=0))

artifact = {
    "model": final_model,
    "features": list(X_train.columns),
    "class_names": list(data.target_names),
}
with open("iris_ensemble.pkl", "wb") as file:
    pickle.dump(artifact, file)

# Trusted artifact only; use matching dependencies when reloading.
with open("iris_ensemble.pkl", "rb") as file:
    restored = pickle.load(file)
assert np.array_equal(predictions, restored["model"].predict(X_test))
if hasattr(final_model, "predict_proba"):
    print("Probability class order:", final_model.classes_)
    print(final_model.predict_proba(X_test.iloc[:1]))
    assert np.allclose(
        final_model.predict_proba(X_test),
        restored["model"].predict_proba(X_test),
    )
print("Export/load parity passed.")
Tiny dataset score differences uncertain ho sakti hain. Ensembles single baseline se better honge, yeh promise nahi. Selection ka best CV mean final performance guarantee nahi; independent test retained hai.

GaussianNB probability calibration imperfect ho sakti hai, so soft-vote example teaching baseline hai. Calibration add karoge toh full preprocessing estimator ke calibration folds ke andar fit ho; validation se benefit check karo. Models reusable objects hain: ensemble fit methods clones/refits manage karte hain.

Stacking Parameters & InferenceVoting & Stacking

Parameter / attributeMeaning
estimatorsNamed base estimators
final_estimatorMeta-model; classifier default LogisticRegression
stack_methodauto or supported predict_proba / decision_function / predict method
cvOOF-generation splitter, not final evaluation score
passthrough=FalseMeta-model receives base outputs only
passthrough=TrueOriginal features also appended to meta-features
estimators_ / final_estimator_Fitted base models / fitted meta-model
transform(X)Outputs meta-feature representation for X

Binary predict_proba stacking mein first probability column from each base model drop hoti hai, because p(0)+p(1)=1. With 3 binary base models → 3 probability meta-features. Iris multiclass has 3 probability columns per model → 9 meta-features when passthrough=False.

stack_method="auto" supported output method choose karta hai. Explicit predict_proba choose karo toh every base estimator ko method support karna hoga. Hard-label codes ko continuous probabilities jaisa treat mat karo without understanding representation.

Passthrough=True raw feature scales meta-model affect kar sakti hain; meta-model Pipeline se appropriate scaling consider karo. Serving uses full-training fitted base outputs, not newly generated OOF folds.

Voting vs Stacking & Common PitfallsVoting & Stacking

DimensionVotingStacking
CombinationFixed count / probability averageLearned meta-model
Training layersBase modelsBase models plus meta-model
OOF requirementNo meta-training layerNeeded for ordinary leakage-safe meta-training
ComputeUsually simpler/lowerRepeated base fits + meta training
InterpretationAggregation rule easy to inspectDepends on meta-model
GuaranteeNo automatic improvementNo automatic improvement
Common mistakes: test-set weight tuning; in-sample meta-features; preprocessing outside internal folds; uncalibrated soft probabilities; confusing internal stacking CV with outer evaluation; assuming more models always help.

One-Minute Revision

Hard = labels. Soft = weighted probabilities. Voting weights fixed; stacking combination learned. Meta-model learns from OOF outputs. Preprocessing stays inside base pipelines. Evaluate complete ensemble on outer CV/final test. Export complete fitted estimator, not only meta-model.

Practice quest

Default lab mein hard/soft disagreement explain karo. One model weight=0 set karke effect dekho. Training-only CV par hard, soft and stack compare karo; runtime and variation report karo. Final test once evaluate karke deployed model freeze karo.
