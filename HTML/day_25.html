Naive Bayes ka IntuitionNaive Bayes Classification

Naive Bayes ek supervised probabilistic classifier hai. Class ki prior probability aur observed features ki class-conditional likelihood combine karke posterior estimate karta hai. Highest posterior wali class usually prediction hoti hai.

Non-technical example: message spam hai?
Message mein “offer” aur “urgent” words aaye. Past labeled messages se seekhte hain: spam kitna common hai, aur spam/non-spam messages mein ye words kitni baar present hote hain. New message ki evidence ke saath initial belief update karte hain.

Bayes

Prior belief ko evidence se update karne ka probability rule.

Naive

Features ko class given hone par conditionally independent assume karta hai. Unconditionally independent hona required nahi.

Binary aur multiclass dono tasks support kar sakta hai. Common use: text classification, spam filtering, document categories aur fast tabular baselines. Model ko labeled training examples chahiye.

Conditional Independence & Log ScoresNaive Bayes Classification

P(X|C)≈∏j=1DP(xj|C)

D = feature count. Within each class, feature likelihoods multiply. Real text words correlate: “credit” and “card” ka co-occurrence independent nahi. Model useful classification phir bhi de sakta hai, lekin correlated/repeated evidence probabilities overconfident bana sakti hai.

score(C)=logP(C)+∑j=1DlogP(xj|C)

Many tiny probabilities multiply karne se floating-point underflow ho sakta hai. Libraries log-likelihood sums aur numerically stable normalization use karti hain. Below lab only two features use karta hai, so direct products easy to inspect hain.

Naive Bayes class probabilities automatically calibrated confidence nahi. High predict_proba value ko guaranteed correctness mat samjho; validation/calibration check karo when probabilities matter.

Worked Example: Offer + UrgentNaive Bayes Classification

Binary word-presence features consider karo. Message mein both words present hain. Assume below class-conditional probabilities fitted/known hain:

QuantitySpamNon-spam
Class prior0.400.60
P(offer present | class)0.800.10
P(urgent present | class)0.700.20
Unnormalized score0.40 × 0.80 × 0.70 = 0.2240.60 × 0.10 × 0.20 = 0.012

Total modeled evidence = 0.224 + 0.012 = 0.236.

P(Spam|both present)=0.2240.236≈0.9492

Non-spam posterior ≈ 0.0508. Model prediction = Spam. This is a Bernoulli presence-feature example, not a full token-count Multinomial model.

Word absent ho toh Bernoulli likelihood mein 1 − P(word present | class) use hota hai. Absence is evidence too. Multinomial token-count model generally present token counts ko score karta hai; dono formulations interchangeably use mat karo.

p(x|C)=12πσC2e−(x−μC)22σC2

Each feature ka class-wise mean/variance learn hota hai. Continuous case mein likelihood density hai, exact point probability nahi; density values 1 se greater bhi ho sakti hain.

MultinomialNB/ComplementNB negative feature values accept nahi karte. Text counts ko centered StandardScaler se negative banana wrong workflow hai. GaussianNB ko sparse text counts ka default model mat samjho.

Zero Frequency & Laplace SmoothingNaive Bayes Classification

A feature event class mein never observed ho, unsmoothed likelihood zero ho sakti hai. Product ka whole score zero ho jaata hai even if other evidence class favor kare. Additive smoothing discrete feature models ko zero-count events handle karne mein help karta hai.

P(xj=1|C)=NCj+αNC+2α

Bernoulli formula: NCj class C ke documents jahan feature present hai; NC total class documents. Two outcomes (present/absent) se denominator mein 2α aata hai. NC=5, present count=0, α=1 → probability = 1/7, not zero.

Multinomial token model mein formula different hai: (token count in class + α) / (total token counts in class + α·V), where V = vocabulary size. α=1 Laplace smoothing; positive other α values additive/Lidstone smoothing.

Tune alpha with training-only CV. GaussianNB ka var_smoothing variance stabilization parameter hai, discrete alpha smoothing ke same formula ka replacement nahi.

Training vocabulary ke bahar word CountVectorizer normally ignore karta hai. Smoothing existing modeled vocabulary ke class counts address karta hai; automatically unseen token ka new vocabulary entry create nahi karta.

Python: Gaussian & Text ClassificationNaive Bayes Classification

Dependencies: pip install scikit-learn numpy. Each example below is standalone and uses local data.

Python • GaussianNB on Iris
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split, StratifiedKFold, GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.naive_bayes import GaussianNB
from sklearn.metrics import classification_report

data = load_iris(as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(
    data.data, data.target, test_size=0.20,
    stratify=data.target, random_state=42
)
pipeline = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("nb", GaussianNB()),
])
search = GridSearchCV(
    pipeline, {"nb__var_smoothing": [1e-11, 1e-9, 1e-7]},
    scoring="f1_macro",
    cv=StratifiedKFold(n_splits=5, shuffle=True, random_state=42),
    refit=True, error_score="raise",
)
search.fit(X_train, y_train)
print("Best parameters:", search.best_params_)
print(classification_report(
    y_test, search.predict(X_test), zero_division=0
))
print("Classes:", search.best_estimator_.named_steps["nb"].classes_)
print("Probabilities:", search.predict_proba(X_test.iloc[:1]))

Iris has no missing values; imputer complete preprocessing pattern demonstrate karta hai. Learned preprocessing CV ke andar hai. GaussianNB generally distance-based scaling require nahi karta; representation and density assumptions still validate karo.

Python • CountVectorizer + MultinomialNB
from sklearn.model_selection import train_test_split, GridSearchCV, StratifiedKFold
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.pipeline import Pipeline
from sklearn.naive_bayes import MultinomialNB
from sklearn.metrics import classification_report

spam = [
    "free prize claim now", "urgent offer win money",
    "claim your free reward", "exclusive prize offer",
    "win cash reward today", "limited offer claim bonus",
    "urgent cash prize", "free bonus for winner",
    "reward money claim today", "exclusive free cash offer",
]
ham = [
    "team meeting tomorrow", "project report is ready",
    "please review meeting notes", "lunch with team today",
    "report deadline tomorrow", "project update for review",
    "schedule team discussion", "meeting agenda attached",
    "please send project notes", "lunch schedule tomorrow",
]
texts, labels = spam + ham, [1] * len(spam) + [0] * len(ham)
train_texts, test_texts, train_y, test_y = train_test_split(
    texts, labels, test_size=0.20, stratify=labels, random_state=42
)
pipeline = Pipeline([
    ("words", CountVectorizer()),
    ("nb", MultinomialNB()),
])
search = GridSearchCV(
    pipeline, {"nb__alpha": [0.5, 1.0, 2.0]},
    scoring="f1_macro",
    cv=StratifiedKFold(n_splits=3, shuffle=True, random_state=42),
    refit=True, error_score="raise",
)
search.fit(train_texts, train_y)
print(classification_report(
    test_y, search.predict(test_texts), zero_division=0
))
print("Class order:", search.best_estimator_.named_steps["nb"].classes_)
print("New message:", search.predict(["urgent free prize"]))
print("Probabilities:", search.predict_proba(["urgent free prize"]))
Tiny handcrafted corpus sirf runnable teaching demo hai. Real spam performance claim nahi; realistic labeled dataset, sufficient class samples, representative splits aur precision/recall evaluation needed hain. Vocabulary CV training folds se learn hoti hai because vectorizer inside Pipeline hai.
Python • Verify the worked Bernoulli example
import numpy as np
from sklearn.naive_bayes import BernoulliNB

# Columns: offer present, urgent present.
# Spam likelihoods: 8/10 and 7/10; non-spam: 1/10 and 2/10.
spam_X = [[1, 1]] * 7 + [[1, 0]] + [[0, 0]] * 2
ham_X = [[1, 1]] + [[0, 1]] + [[0, 0]] * 8
X = np.array(ham_X + spam_X)
y = np.array([0] * 10 + [1] * 10)

# Explicit priors intentionally differ from the balanced sample counts.
# alpha=0 is ONLY for this exact non-zero-likelihood arithmetic check.
model = BernoulliNB(
    alpha=0.0, binarize=None, class_prior=[0.6, 0.4]
)
model.fit(X, y)
probabilities = model.predict_proba([[1, 1]])[0]
expected = np.array([0.012, 0.224]) / 0.236
assert np.allclose(probabilities, expected)
print("Class order:", model.classes_)
print("Posterior:", probabilities)
print("Prediction:", model.predict([[1, 1]]))

Production baseline mein positive alpha safer candidate hai; tiny/zero alpha numerical issues create kar sakta hai when zero counts exist. This example every feature outcome ko non-zero class frequency deta hai and manually set priors verify karta hai.

Evaluation, Imbalance & DeploymentNaive Bayes Classification

Class imbalance mein accuracy alone misleading ho sakti hai. Spam ko positive class declare karke precision, recall, F1 aur confusion matrix inspect karo. Legitimate message wrongly blocked hona false positive; actual spam miss hona false negative.

Prior matters

Class frequencies estimated priors influence karti hain. Deployment prevalence change ho toh decisions/probabilities affect ho sakti hain.

Threshold matters

Highest posterior baseline ke beyond spam threshold task cost ke according choose karo, using training/validation—not final test.

ComplementNB imbalanced text tasks ke liye useful comparison candidate hai, automatic fix nahi. Duplicated/correlated features, vocabulary leakage and shifted language real-world performance affect kar sakte hain.

Deployment mein full text vectorizer + classifier Pipeline save karo. User raw text saved Pipeline ko pass kare; serving app mein vocabulary refit mat karo. Pickle only trusted source se load karo and dependency versions match karo.

Common Mistakes & Quick RevisionNaive Bayes Classification

MistakeBetter habit
P(word|spam) = P(spam|word) assumePrior and normalization include karo
Naive means all features globally independentConditional independence given class samjho
Gaussian probability density treated as point probabilityDensity vs probability distinguish karo
Multinomial input has negative centered featuresNon-negative counts/appropriate weights use karo
Bernoulli ignores absent wordsAbsence contributes 1−p likelihood
Vocabulary built from full dataset before splitVectorizer inside CV Pipeline
alpha and var_smoothing interchangeableDiscrete count smoothing vs variance stabilization
High posterior is guaranteed truthValidate calibration and dataset shift

One-Minute Revision

Posterior ∝ prior × likelihood. Naive assumption = class-conditional feature independence. Use log scores for many features. Gaussian = numeric densities; Multinomial = non-negative counts; Bernoulli = binary presence/absence. Smooth discrete counts. Fit preprocessing inside CV. Evaluate probabilities cautiously.
